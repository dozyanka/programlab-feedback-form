# FormLab — форма обратной связи

Адаптивная форма обратной связи на **PHP 8.2+ / JavaScript / CSS**. Выполнена в качестве тестового задания на позицию PHP-разработчика (Middle/Senior). Всё обязательное из технического задания реализовано; четыре дополнительных пункта также включены.

## Что умеет

- Тема (select), ФИО, телефон, e-mail, сообщение, CAPTCHA, согласие на обработку персональных данных и скрытое поле `action=message`.
- Двойная валидация: JavaScript перед отправкой и PHP независимо от JavaScript; ошибки рядом с полями и общее уведомление.
- Обязательность всех полей, проверка формата российского телефона и e-mail, ограничения **255 символов для текстовых полей** и **4096 для сообщения** (по символам Unicode, а не байтам UTF-8).
- Отправка через **Fetch API / AJAX** без перезагрузки, маска номера `+7 (999) 123-45-67`.
- Авторская графическая CAPTCHA, привязанная к PHP-сессии, одноразовая и действующая 5 минут, с кнопкой обновления.
- После успешной валидации письмо отправляется **на e-mail, введённый посетителем** — именно так сформулирован пункт 3 тестового задания.
- Адаптивная вёрстка, доступные подписи, индикация загрузки, `aria-invalid`, клавиатурная навигация, live-области уведомлений.

## Быстрый запуск через Docker

Нужны **Docker Desktop** (с запущенным движком) и Docker Compose V2.

```powershell
docker compose up --build -d
```

Затем откройте:

| Адрес | Назначение |
|---|---|
| `http://localhost:8080` | Форма обратной связи |
| `http://localhost:8025` | Mailpit: интерфейс тестовой почты |

Для проверки выберите тему, введите ФИО, номер, любой корректный тестовый e-mail (например, `tester@example.com`), сообщение, CAPTCHA, согласие и отправьте. **Письмо появится в Mailpit** — оно не отправляется на внешний адрес, это безопасный локальный SMTP-приёмник. Внутри письма указан введённый e-mail в качестве адресата.

```powershell
# Просмотр логов
docker compose logs -f web

# Проверка PHP и запуска тестов внутри контейнера
docker compose exec web php tests/run.php

# Остановить сервисы
docker compose down
```

Файлы состояния rate limiter хранятся в именованном томе Docker; чтобы удалить и его, используйте `docker compose down -v` (удалит данные лимитов).

## Запуск без Docker

Требуются PHP 8.2+, расширения `gd` и `pdo_sqlite`, **Composer**, запущенный SMTP-сервер, доступный по сети. Приложение не использует PHP-framework; библиотека PHPMailer устанавливается через Composer:

```powershell
composer install
New-Item -ItemType Directory -Force storage | Out-Null
$env:SMTP_HOST = "127.0.0.1"
$env:SMTP_PORT = "1025"
$env:MAIL_FROM_ADDRESS = "noreply@example.test"
$env:APP_KEY = "change-me-please-use-a-long-random-value"
php -S 127.0.0.1:8080 -t public
```

Для локальной почты можно запустить Mailpit отдельно. **Не используйте `php -S` как production-сервер.** При работе с реальной почтой задайте SMTP-хост, порт, имя пользователя, пароль и `SMTP_ENCRYPTION=tls` или `ssl` через защищённые переменные окружения. `MAIL_FROM_ADDRESS` должен соответствовать политике вашего SMTP-провайдера. Не выкладывайте секреты в репозиторий.

## Конфигурация

| Переменная | Назначение |
|---|---|
| `SMTP_HOST`, `SMTP_PORT` | Сервер и порт SMTP |
| `SMTP_USERNAME`, `SMTP_PASSWORD` | Авторизация SMTP, если требуется |
| `SMTP_ENCRYPTION` | `tls` / `ssl` / пусто для локального Mailpit |
| `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME` | Отправитель письма |
| `APP_KEY` | Секрет для HMAC-идентификаторов rate limiter |

Для Docker Compose значения `APP_KEY` и SMTP-переменных считываются из `.env`, если он создан на основе `.env.example`. Для локального тестирования Compose содержит небезопасное значение по умолчанию. Для публичного размещения **обязательно замените** его криптографически случайным секретом (например: `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"`).

## HTTP API

- `GET /` — HTML-страница со случайным CSRF-токеном, сохраняющимся в сессии.
- `GET /api/captcha.php` — новое изображение PNG; предыдущий CAPTCHA-код становится недействительным.
- `POST /api/submit.php` — `multipart/form-data`/обычный form POST, ответ в JSON.

Успешный ответ (`200`):

```json
{"success":true,"message":"Готово! Копия обращения отправлена на указанную почту.","errors":{},"captcha_refresh":true}
```

Ошибки валидации (`422`):

```json
{"success":false,"message":"Проверьте выделенные поля и отправьте форму ещё раз.","errors":{"email":"Укажите корректный адрес электронной почты."},"captcha_refresh":true}
```

Возможные коды: `400` (некорректное действие), `403` (CSRF), `405` (метод), `422` (валидация), `429` (лимит запросов), `503` (недоступен SMTP/сервис).

## Архитектура

```text
public/
  index.php            HTML-разметка и выдача CSRF-токена
  api/captcha.php      выдача изображения CAPTCHA
  api/submit.php       JSON-контроллер
  assets/              CSS, JS, favicon
src/
  FeedbackValidator.php  правила валидации и нормализация
  Captcha.php            генерация и проверка одноразового кода
  FeedbackMailer.php     отправка почты через SMTP/PHPMailer
  RateLimiter.php        атомарные лимиты по IP на SQLite
  Session.php            настройки PHP-сессии и CSRF
  Config.php             конфигурация из окружения
tests/run.php            независимые проверки валидации и защиты
storage/                SQLite (не публикуется)
Dockerfile, compose.yaml развёртывание + Mailpit
.github/workflows/ci.yml  CI для PHP, JS и автопроверок
```

**Защитные меры:** неизменяемый список тем, серверная повторная проверка, CSRF, honeypot, одноразовая CAPTCHA, лимиты **15 запросов / 15 минут** и **3 отправленных обращения / час** на IP, HTTP-заголовки защиты, недоступность `storage/` из web-root, ошибки SMTP только в серверных логах, отсутствие паролей в клиенте, данные письма в plain text (без HTML-инъекций).

> Ограничения демонстрационного проекта: собственная графическая CAPTCHA не рассчитана на профессиональную защиту от распознавания изображений и имеет ограниченную доступность. SQLite хорошо подходит для тестового задания и небольшого сервиса, но для большого распределённого приложения лимиты следует вынести в Redis, отправку почты — в асинхронную очередь, а CAPTCHA заменить специализированным защищённым сервисом с доступной альтернативой. Публичное развёртывание потребует TLS, надёжной доставки почты, отдельной политики обработки данных и мониторинга.

## Проверка

```powershell
php tests/run.php
node --check public/assets/app.js
```

При запуске тестов непосредственно на ПК без `gd`/`pdo_sqlite` соответствующие проверки будут пропущены. В Docker есть обе зависимости. CI также проверяет PHP-синтаксис на PHP 8.3 и выполняет тесты.

Рекомендуемое ручное тестирование:

1. Попробовать отправить пустую форму: ошибки под обязательными полями, без запроса к серверу.
2. Проверить неверный e-mail, незаполненный телефон, более 255 символов в ФИО, более 4096 символов в сообщении (обойти `maxlength` через DevTools для проверки сервера).
3. Проверить неверный код CAPTCHA, а затем верный обновлённый код.
4. Проверить отправку с валидными значениями и письмо с адресатом в Mailpit.
5. Проверить адаптацию на 375 px и широкой ширине, TAB-навигацию.
6. Убедиться, что повторный POST с использованной CAPTCHA не отправляет второе письмо.

## Стек

PHP 8.2+, HTML5, CSS3, JavaScript ES2020+, PHPMailer, SQLite (rate limiting), Docker/Apache, Mailpit, GitHub Actions. База данных для хранения обращений не нужна, поскольку ТЗ требует отправки уведомления, а не сохранения заявок.
